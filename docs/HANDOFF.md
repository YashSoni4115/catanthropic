## Spec R3: belief features in PPO training (roadmap 3)
Goal: test whether the existing belief action features (robber steal, monopoly, year of plenty) improve the PPO policy beyond B3.
Why now: B3 passed. The gains from continuation are shrinking. The features are already extracted and leak-tested (`test_belief_features_leak_free`), but `train.py` exits on `--belief-features`.
Scope (dev):
- Wire `catan_rl/rl/belief_features.py` (DIM=9) into the action features used by `net.py`, `rollout.py`, `agent.py` (PPOAgent), and `train.py`, behind `--belief-features`.
- Add a warm start from a non-belief checkpoint: the new input weights start at zero, so at update 0 the policy is identical to B3 (test: same logits on a fixed state).
- The checkpoint records `belief_features: true`. PPOAgent and final_eval/eval.run load it correctly.
- League past-checkpoint opponents without belief features must still load.
- Out of scope: discard/monopoly-timing helpers, Phi changes, new features.
Tests:
- Zero-init equivalence.
- Leak test through the full agent path: the agent's action distribution is unchanged when opponents' hidden hands and dev cards are resampled consistent with public info (extend the existing determinize-style test).
- Hash-order determinism.
- The full suite stays green.
Run (after reviewer PASS): `--init-from checkpoints/ppo_B3_600.pt --belief-features --seed 4`, the same hyperparameters as B3, 600 updates, about 3.5h.
- Control: the same run with no `--belief-features` and `--seed 4`, so that the only difference is the features. That is another 3.5h. Run both back to back overnight.
Seeds: training seed 4, so game seeds 5,000,000+. Validation 9000-9249, new.
Gates (fresh seeds 9000+, seed-clustered, paired R3 vs control vs 3 value_function):
- PASS: diff CI lower bound > 0, AND vs_ab not worse than control (diff CI upper bound >= 0), AND vs_wr >= 0.95.
  - Action: adopt belief features; next, add the analytic helpers (discard, monopoly timing).
- NULL: the diff CI contains 0.
  - Action: keep features off. Check whether the policy uses them (weight norms, KL by robber/monopoly action type) before more work. Move to roadmap 1.
- FAIL: diff CI upper bound < 0.
  - Action: suspect a bug or a feature-scale problem. Diagnose before any further runs.
Risks / leak surface: the belief tracker must use public events only; dev-buy and steal identities must never leak. The reviewer must check the rollout path, not only the extractor.

## Spec V0: B2 fresh-seed validation
Goal: get an unbiased headline for `checkpoints/ppo_B2_600.pt` and apply the roadmap-0 decision gates.
Why now: roadmap 0. B2's only number (0.437) is on training eval seeds 0-62. B313's 0.294 was picked on 5000-5249 (selection bias).
Scope: run `catan_rl.rl.final_eval` only. Out of scope: any code, belief features, retraining.
Deliverables: `runs/rl/B2_val/results.json`, `runs/rl/B2_val_ab/results.json`, and gate numbers added to `docs/baselines.md` (via `scribe`).
Seeds (already reserved): 6000-6249 for vs_vf; 6000-6124 for vs_wr, vs_bc, vs_b313, vs_ab. The 7000-7099 range is held back for the behavior profile and KL diagnosis (Spec V1).
Runs (checkpoints: bc, B313, B2):
1. `scripts/notify_run.sh B2_val -- .venv-rl/bin/python -m catan_rl.rl.final_eval --ckpts checkpoints/ppo_B313.pt,checkpoints/ppo_B2_600.pt --seed-base 6000 --only vs_vf,vs_bc,vs_b313,vs_wr --out runs/rl/B2_val`
2. `scripts/notify_run.sh B2_val_ab -- .venv-rl/bin/python -m catan_rl.rl.final_eval --ckpts checkpoints/ppo_B2_600.pt --seed-base 6000 --only vs_ab --out runs/rl/B2_val_ab`
   - alpha_beta is slow, about 1.7 games/s, so start this after run 1 finishes.
Gates (seed-clustered 95% CI, slot 0, written before the run):
- REAL IMPROVEMENT: the B2 vs_bc CI lower bound is > 0.25, AND B2 vs_ab (B2 vs 3 alpha_beta) CI lower bound > 0.25 (beats alpha_beta), AND the B2 vs_b313 CI lower bound is >= 0.25.
  - Action: continue training from B2 (new seed range from 1,000,000+N, recorded first). Then Spec for belief features on robber/monopoly.
- EXPLOIT: the B2 vs_vf CI lower bound is > the B313 vs_vf CI upper bound, but the B2 vs_bc or vs_b313 CI lower bound is < 0.25.
  - Action: cut the value_function league share, raise the self-play and past-checkpoint share, retrain from B313.
- REGRESSION: the B2 vs_wr win rate is < 0.95, or the B2 vs_vf point estimate is <= B313's on the same seeds.
  - Action: stop. Diagnose with Spec V1 (profile + KL) before any training.
- AMBIGUOUS (any deciding CI straddles 0.25 or overlaps B313):
  - Action: extend vs_bc and vs_b313 to 250 seeds (6000-6249). If it is still ambiguous, treat it as no improvement and run Spec V1.
- Regardless of outcome, flag: a turn-limit rate > 2% or a VP-source skew counts as an "odd profile" and triggers Spec V1 first.
Runtime: run 1 takes roughly 15-25 min (vf is about 4 games/s and the 3000 vf-heavy games dominate). Run 2 is about 125x4 / 1.7 ≈ 5 min per ckpt plus the bc reference, so about 10-15 min. Both go through the notifier (caffeinate nohup).
Risks / leak surface: none, eval only and non-peeking. alpha_beta and value_function are peeking baselines, so note that in the report.
